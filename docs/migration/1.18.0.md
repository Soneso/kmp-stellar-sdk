# Migrating to 1.18.0

This guide covers the observable changes between 1.17.0 and 1.18.0. If you upgrade from an older version, also review the CHANGELOG between your version and 1.17.0 and the earlier migration guides, newest first: [1.15.0](1.15.0.md), [1.12.0](1.12.0.md). Each note describes one situation: whether you are affected, how it shows, and what to do.

## Smart account context rule types

- If you match with `when` over `ContextRuleType` without an `else` branch: in 1.18.0 the match does not compile, because the type gains `ContextRuleType.CreateContractExternalRef(owner, tag)`, the rule for contracts deployed from an executable reference. `listContextRules` returns such rules, and the kit signs for wallets that hold one. In 1.17.0 `listContextRules` and the kit's signing operations on such a wallet threw `ValidationException.InvalidInput` with `Invalid input for context_type: Unknown context_type discriminant: CreateContractExternalRef`. Add a `CreateContractExternalRef` branch or an `else` branch. Code that caught that exception receives the rule instead.

## Smart account Delegated signers

- If you add a contract (`C...`) as a Delegated signer, with `OZSignerManager.addDelegated` or in the `signers` of `OZContextRuleManager.addContextRule`: in 1.18.0 the call throws `ValidationException.InvalidAddress` with `Invalid address: A delegated signer must be a Stellar account (G-address), got: <address>. Delegating to a contract can let anyone authorize the account.`, and for the wallet itself `ValidationException.InvalidInput` with `Invalid input for signer: The smart account <wallet> cannot be its own delegated signer`. In 1.17.0 the SDK did not apply these signer checks. Pass the Stellar account (`G...`) that should sign.

- If you build an `add_signer`, `batch_add_signer` or `add_context_rule` call on the wallet yourself and submit it through `kit.transactionOperations` or `kit.multiSignerManager`: in 1.18.0, after a successful simulation, the SDK applies the previous note's checks before requesting signatures. A self delegate can fail earlier with `TransactionException.SimulationFailed` reporting 3018 (`SelfDelegatedSigner`). A muxed contract address (`W...`) gives `ValidationException.InvalidInput` with `Invalid input for signer: Delegated signer address has an unsupported address type: SC_ADDRESS_TYPE_MUXED_CONTRACT, got: <address>`, and with `External signer verifier address` in place of `Delegated signer address` for an External verifier. In 1.17.0 the SDK did not apply these signer checks. Pass an account (`G...`) as delegate, and the contract behind a muxed verifier, `MuxedContract(address).contractId`.

- If a wallet you sign for already holds a Delegated signer with a contract address: in 1.18.0 the kit reads that signer and signs for the wallet, and the SDK update does not close the gap it opens (GHSA-jpg9-m7w4-c7wc). In 1.17.0 the kit read and signed the same way. Remove such a signer with `OZSignerManager.removeSigner`, or upgrade the wallet, and every smart account it delegates to, to stellar-accounts 0.7.3 or 0.8.0.
