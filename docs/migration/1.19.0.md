# Migrating to 1.19.0

This guide covers the observable changes between 1.18.0 and 1.19.0. If you upgrade from an older version, also review the CHANGELOG between your version and 1.18.0 and the earlier migration guides, newest first: [1.18.0](1.18.0.md), [1.15.0](1.15.0.md), [1.12.0](1.12.0.md). Each note describes one situation: whether you are affected, how it shows, and what to do.

Code that builds `SCStringXdr`, `SCSymbolXdr` or `MemoXdr.Text` values from valid text and reads their `value` needs no source change, unless it calls `copy()` on a `MemoXdr.Text` or destructures one. On the JVM and Android, recompile code that uses `SCStringXdr` or `SCSymbolXdr` or calls an API that exposes them, and use libraries rebuilt against 1.19.0.

- If you run JVM or Android code compiled against 1.18.0 that constructs or accesses `SCStringXdr` or `SCSymbolXdr`, or calls an API that takes or returns them, such as a library built against 1.18.0: in 1.19.0 both are classes that store the bytes of the string, so the JVM signatures of these types and of the functions that expose them change. Such code can fail with linkage errors such as `NoSuchMethodError`. In 1.18.0 both were value classes over a `String`. Recompile the affected code against 1.19.0, and use libraries rebuilt against 1.19.0.

- If you read `value` of an `SCStringXdr`, `SCSymbolXdr` or `MemoXdr.Text` decoded from XDR, directly or through `Scv.fromString` or `Scv.fromSymbol`, such as a contract result or a transaction memo: in 1.19.0 `value` throws `CharacterCodingException` for bytes that are not valid UTF-8, and `bytes` returns the exact bytes. In 1.18.0 decoding replaced such bytes with the replacement character U+FFFD, and `value` returned that text. Catch `CharacterCodingException` where such a value arrives, and read `bytes` when you need the data; `SCStringXdr(bytes)`, `SCSymbolXdr(bytes)` and `MemoXdr.Text(bytes)` keep them. Text that is valid UTF-8 reads as before.

- If you call `copy()` on a `MemoXdr.Text` or destructure one, as in `val (text) = memo`: in 1.19.0 the code does not compile, because `MemoXdr.Text` is a class that stores the bytes of the memo text and has no `copy` or `component1`. In 1.18.0 it was a data class over the text. Build the new value with a constructor, and read the text with `value`.

  ```kotlin
  // 1.18.0
  import com.soneso.stellar.sdk.xdr.MemoXdr

  fun updateMemo(memo: MemoXdr.Text) {
      val changed = memo.copy(value = "paid")
      val (text) = memo
  }
  ```

  ```kotlin
  // 1.19.0
  import com.soneso.stellar.sdk.xdr.MemoXdr

  fun updateMemo(memo: MemoXdr.Text) {
      val changed = MemoXdr.Text("paid")
      val text = memo.value
  }
  ```
